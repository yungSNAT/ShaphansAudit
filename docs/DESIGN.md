# Design

`shaphan` reads the transcripts that Claude Code and Codex write on your machine and reports where tokens and checks are wasted. It prints names, paths, counts, sizes and times, as listed under Privacy. It never prints message text, tool inputs or tool outputs, and it makes no network calls.

Leave usage and cost totals to [ccusage](https://github.com/ryoppippi/ccusage); `shaphan` looks for waste that totals cannot show.

## Detectors

| Subcommand | Agents | Reports |
|---|---|---|
| `startup` | Claude | Characters loaded before the first reply of each main session, by source: instruction files, hook output, skill and agent listings, tool schemas, MCP instructions and other attachments; also the input tokens Claude Code recorded for that first reply |
| `schemas` | Claude | Per tool, or per MCP server: sessions whose requests loaded its schema, sessions that called it, and the characters loaded in sessions that never called it. A tool only ever sent with `defer_loading` gets no row: its schema enters context through ToolSearch results, which v0.1 does not measure |
| `pipes` | Claude | Test runs piped straight into `tail` or `head` without `pipefail` or `PIPESTATUS`, and how many of those printed a failure whilst the call reported success |
| `polls` | Claude, Codex | Commands repeated exactly within a session, split into repeats with no file edit since the previous run (polls) and reruns after an edit; for Claude, also the polls of a command whose last result was an error and the characters polls returned |
| `rereads` | Claude, Codex | Files read again after a context compaction that had been read before it; for Claude, also the characters those re-reads returned |
| `hooks` | Claude | Hook runs, cancellations, timeouts and durations, by event, matcher and hook |

`shaphan all` runs every detector in one pass over the files.

Coverage limits in v0.1: `startup`, `schemas`, `pipes` and `hooks` read Claude transcripts only. `pipes` judges local Bash commands only; commands sent over `ssh` are counted but not judged, because the remote shell's settings are unknown. Test runners inside shell functions or `bash -c` scripts are not recognised. Codex runs PowerShell, where a pipe does not hide a native command's exit status in the same way. `polls` and `rereads` read Codex calls but not their results, so the columns that need a result (`polls_after_failure`, `poll_chars` and `reread_chars`) are empty for Codex. A Codex `exec` call can run several commands and returns one output with no error flag, so its result cannot be tied to one command; the outputs of `function_call` records have not been examined.

## Inputs

- Claude Code: `~/.claude/projects/**/*.jsonl`. A file under a `subagents` folder is a subagent session. Records used: `assistant` (`tool_use` blocks), `user` (`tool_result` blocks), `attachment` (instruction files, hooks, listings, deltas), `system` with subtype `compact_boundary`, and `api-request-shape` (the tool definitions sent with a request; a tool with `defer_loading: true` is not loaded into context).
- Codex: `~/.codex/sessions/**/*.jsonl` and `~/.codex/archived_sessions/**/*.jsonl`, where Codex moves older sessions. Compressed `*.jsonl.zst` transcripts are counted as skipped, not read. The first record, `session_meta`, marks a subagent session by its `parent_thread_id`. Records used: `custom_tool_call` named `exec`, whose input is code calling `tools.exec_command({cmd: ...})`, `readFile(...)` or `readFileSync(...)`, and the edits `apply_patch(...)`, `writeFile(...)` or `writeFileSync(...)`, taken in source order, skipping the text of patch bodies (from a string that opens with `*** Begin Patch` to `*** End Patch`, unless the quote follows `//` on its line other than in `://`), which is written, not run; `function_call` named `apply_patch` (an edit) or with a `cmd` or `command` argument; and `compacted`.

Both formats are undocumented and change between releases. `shaphan` skips a line that is cut short (does not end in `}`) or that a detector needs but cannot parse, and reports how many it skipped; it counts unreadable files and folders and never fails a run because of one. A file is read only if it was modified at or after `--since`; within it, a record counts only if its own timestamp is at or after `--since`. A record without a timestamp takes the last one seen in its file. Only the roots of agents that a chosen detector reads are scanned and listed. Session state, such as which files were read before a compaction, is built from the whole file, so a re-read early in the window is still recognised. A file is read only as far as some chosen detector still needs it: `startup` alone stops at a main session's first reply, so lines after it are neither read nor counted as skipped.

## Measures

- Sizes are characters (Unicode scalar values) of the text as stored, or of compact JSON for structured values. A tool result's size is the characters of its text: a string, or the text blocks of a list. A block without text, such as an image, adds nothing.
- Tokens come from the transcript only where Claude Code records them: a first request's tokens are the `input_tokens`, `cache_creation_input_tokens` and `cache_read_input_tokens` of the session's first reply. `sessions_with_request_tokens` counts the measured sessions whose first reply records them, and whose sum fits in 64 bits. A reply with model `<synthetic>`, which Claude Code writes itself, such as an error notice, follows no request, so it is not a first reply: `startup` reads on to the next reply, and a session with no other reply is not measured. Columns ending in `_tokens_est` are estimates, the characters beside them divided by 4 and rounded up in each row, so rows need not add up to a total; the model's own tokenizer, which is not published, gives a different count.
- Commands are split into simple commands at unquoted `|`, `|&`, `||`, `;`, `&`, `&&` and newlines. `#` comments, heredoc bodies (also when written `cat<<EOF`) and PowerShell here-string bodies (from `@'` or `@"` to `'@` or `"@`) are skipped. Backslash escapes, `$(...)` and backticks are not parsed. A Codex `function_call` whose argument list starts with a shell is judged by the element after `-c`, `-lc`, `-Command` or `/c`; any other list is joined with spaces.
- A command's verb class is its first word, lower-cased and without a path or `.exe`, after skipping `VAR=value` assignments, leading segments that are only assignments or `cd <dir>`, and the prefixes `rtk`, `rtk bypass`, `rtk proxy`, `rtk test`, `rtk err`, `sudo` and `time` with their options. A command that is only assignments, including a PowerShell assignment such as `$x = 1` or `$env:KEY='v'`, gives `(assignment)`: an assigned value is never read as a command. For `ssh`, the class is `ssh <remote verb>`; the host is not printed, since a misparse can put a value in its place. A first word that is not a program name (ASCII letters, digits, `.`, `_`, `+` and `-`), such as a variable or a URL, gives `(other)`. The word must also name a program on this machine: a shell builtin, alias or common command from a fixed list, a common PowerShell cmdlet from a fixed list, a program on `PATH` (only absolute folders are searched; on Windows a file with no extension or one in `PATHEXT`, elsewhere a file with an execute bit), or, for a word with a folder in it, an existing file with a program or script extension. Otherwise the class is `(other)`. A word that starts like a network share or a Windows device path (2 slashes or backslashes, or one followed by `?`) is never looked up on disk, because the lookup would contact the host it names; only its file name is checked against the lists and `PATH`. A path that only the system maps to a network location is looked up like a local path: a drive letter mapped to a share, a link to one, an automounted folder such as `/net/<host>` or a relative path when the current folder is on a share. Parsing is heuristic, and this check keeps a value that lands in a program's place, such as an item of a multi-line array or a quoted literal piped to a command, out of the output.
- A test run is a simple command that starts with a test runner (`cargo test`, `cargo nextest run`, `pytest`, `vitest`, `jest`, `node --test`, `npm test`, `npm run test`, `go test` or `dotnet test`, optionally behind `npx`, `bunx`, `uv run`, `poetry run`, `python -m`, `python3 -m` or `py -m`), possibly after the wrappers `agent-heavy`, `nice`, `timeout`, `env`, `nohup`, `time`, `sudo`, `rtk test`, `rtk err`, `do` or `then` with their options and numeric arguments. A runner named in other text, such as `echo cargo test`, is not a test run. It is piped when a single `|` sends it straight into `tail` or `head`. An `ssh` command whose remote command is a piped test run counts as over `ssh`; one piped locally into `tail` or `head` is judged as local.
- A read is `Read`, or a `cat`, `head`, `tail`, `sed` (not `sed -i`), `less`, `more`, `bat`, `Get-Content` or `gc` command, or a `readFile` call in Codex code, found by pattern, so a call inside a string that never runs also counts; `$text = Get-Content x.md` reads `x.md`. Option values, such as `bat -l rust` or a heredoc delimiter, are not paths. Arguments holding `$` or starting with `(`, `@` or `{` are variables or expressions, not paths, and are skipped. Paths are compared lower-cased with forward slashes.
- A hook's label is the file name of its script or, when there is no script, its program; arguments never print. The script is the program itself or the first script argument of an interpreter (`node`, `bun`, `deno`, `python`, `python3`, `py`, `uv`, `bash`, `sh`, `zsh`, `pwsh`, `powershell` or `cmd`) before an option with which that interpreter runs inline code: `-e`, `-p`, `--eval` or `--print` for `node`, `bun` and `deno`; `-c` or `-m` for Python and `-c` for `bash`, `sh` and `zsh`, also at the end of a group such as `-lc`; and `-c`, `-Command`, `-ec` or `-EncodedCommand` in any case for PowerShell. It must be an existing file with a script or program extension, and the program must pass the verb-class check above; otherwise the label is `(other)`. A script on a share-style path is not looked up, as above, so its label is `(other)` unless its file name alone names a program. The name must be plain (ASCII letters, digits, `.`, `_`, `+` and `-`). `VAR=value` and PowerShell assignments and a leading `cd` are skipped first. Recent Claude Code versions record `command hook N` (the hook's position under its event and matcher) or the hook's status message in place of the command; `command hook N` is kept whole, and a status message whose first word is not a program gives `(other)`. Hook rows are keyed by the transcript's `hookName`, which joins the event and matcher, such as `PreToolUse:Bash`, or by `hookEvent` when that is missing; a hook with neither is `(unknown)`. A fractional `durationMs` is rounded.
- A re-read is a read, after a compaction, of a file read before it and not yet read since. Reread share divides re-reads by every read in the window for that agent and scope, in compacted sessions or not. Reread characters are the size of the result of each Claude call that made a re-read counted in the window. A call that re-reads 2 files is counted once. A result holds what the tool returned, which can be more or less than the file: `Read` numbers each line and can return part of a file, and a shell command prints whatever it prints.
- A poll after a failure is a poll of a command whose most recent result in the session had `is_error` set, whether or not that run was in the window. Claude Code sets it for a command that exits with an error status and for a call that a hook denied, so a denied call counts although it never ran. Poll characters are the size of the results of the polls counted in the window. A run whose result is not in the transcript adds nothing to either measure, and a failed run followed by an edit and the same command is a rerun, not a poll.

## Privacy

Output holds tool names, MCP server names, instruction file paths, hook names (event and matcher), hook labels, attachment types, entry points, verb classes, the scanned folders, counts, sizes and times. Paths under the home folder print from `~`; other paths print in full. Re-read file paths print only with `--paths`.

A verb class or hook label names only a program found on the machine that runs `shaphan`, so a value from a command prints only if it is also such a name, and the same transcripts can give different labels on another machine.

Fixtures in this repository are synthetic. Tests check, ignoring case, that no sentinel string reaches the output: those in the main fixtures' message text, tool inputs, tool outputs and hook commands, those in the tool outputs of a result-pairing fixture, those in the replies and attachments of a startup tokens fixture, and those in a probe fixture with one on each path found so far by which input text could reach a verb class, hook label or path (PowerShell assignments, hashtables and here-strings, multi-line arrays, comments, heredocs, escaped quotes, `ssh` hosts, URLs, quoted first words, `sudo` and `time` options, reader option values, hook commands, Codex argument lists, `readFile` calls and patch bodies). The probe test also checks that its records reach the detectors. The tests create stub programs and put them first on `PATH`, and their hook commands name stub scripts in `tests/fixtures/hooks`, so their labels do not depend on the machine.

## Interface

```text
shaphan <all|startup|schemas|pipes|polls|rereads|hooks> [--since 7d|24h|YYYY-MM-DD|RFC 3339]
        [--agent claude|codex|all] [--claude-root DIR] [--codex-root DIR] [--json] [--limit N] [--paths]
```

`--since` defaults to `7d`; a bare date means local midnight. `--limit` (default 20) caps each table's rows. `--json` prints one object with `schema_version` 1. Exit codes: 0 success, 1 a runtime error such as a missing transcript folder or a bad `--since`, 2 a usage error.

## Not in v0.1

Large tool results, cache rewrites after idle gaps, colour codes in tool results, Codex startup and tool schemas, Hermes `state.db` and RTK `history.db`.
